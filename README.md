# karatsuba_verilog_generator — генератор конвейерного умножителя по алгоритму Карацубы

Программа на C++ принимает разрядность `N` и генерирует Verilog-описание умножителя двух
неотрицательных `N`-разрядных целых чисел (результат — `2N` бит) по алгоритму Карацубы.
Результат появляется на выходе **на 3-м такте** после подачи входных данных, далее
выдаётся **каждый такт** (конвейер). В сгенерированном коде нет оператора `*`.

Дополнительно программа умеет генерировать самопроверяющийся тестбенч для любого `N`.

## Требования

- Linux
- `g++` с поддержкой C++17, `cmake` ≥ 3.14, `make`
- для тестов: Icarus Verilog (`sudo apt install iverilog`)

## Интерфейс сгенерированного модуля

    module karatsuba_<N> (
        input  logic             clk,
        input  logic [N-1:0]     a,
        input  logic [N-1:0]     b,
        output logic [2*N-1:0]   out
    );

- Вход принимается по переднему фронту `clk` №1, результат стоит на `out` после фронта №3.
- Новую пару можно подавать **каждый такт**; результаты выходят в том же порядке со сдвигом на 3 такта.
- Сброса и сигнала `valid` нет. Пока конвейер не заполнился (первые 2 такта), на `out` неопределённые значения.

## Как устроен умножитель

Пусть `h = ⌊N/2⌋` — ширина младшей части, `l = N − h` — старшей (для нечётного `N` она на бит шире):

    a = a_hi·2^h + a_lo,   b = b_hi·2^h + b_lo

    z0 = a_lo · b_lo
    z2 = a_hi · b_hi
    zm = (a_hi + a_lo) · (b_hi + b_lo)      — сумма имеет l+1 бит (с переносом)
    z1 = zm − z0 − z2
    a·b = z2·2^(2h) + z1·2^h + z0

Вместо четырёх умножений получается три; каждое из них снова раскладывается по Карацубе.

### Конвейер (ровно 3 ступени регистров)

Верхний модуль `karatsuba_<N>` — единственный с регистрами:

1. **Ступень 1.** Разбиение входов и предсложение `a_hi + a_lo`, `b_hi + b_lo`.
2. **Ступень 2.** Три частичных произведения `z0`, `z2`, `zm` (комбинационная рекурсия), результат регистрируется.
3. **Ступень 3.** `z1 = zm − z0 − z2` и итоговая сборка `out`.

Для каждой нужной ширины `w` генерируется один комбинационный модуль `karatsuba_<w>` без `clk`;
повторяющиеся ширины выводятся один раз, поэтому размер файла растёт как O(log N).
Задержка не зависит от `N`: растёт глубина комбинационной логики на ступени 2, а не число тактов.

### Базовый случай и умножение столбиком

Рекурсия заканчивается на ширинах `≤ 3` (для 3 бит сумма половин снова имеет 3 бита, рекурсия не сходилась бы,
поэтому база не может быть меньше 3). Там применяется модуль `mul` — **умножение столбиком**:
для каждого единичного бита `b[i]` к накопителю прибавляется `a`, сдвинутое на `i`.
Оператор `*` не используется.

Для `N ≤ 3` рекурсия не нужна: генерируется конвейер `входы → mul → регистр → выход`, также с задержкой 3 такта.

## Тесты

### Проверка сгенерированного:
  1. Собрать проект

    make

  2. Запустить тесты

    make test
    
    # ожидаемый вывод: 
    RUNNING TEST FOR N=<n>
    PASSED: N=<n>
  
  3. Очистить директорию от папки с тестами
    
    make clean
  Тесты проводятся для N = [1, 2, 3, 4, 5, 7, 8, 9, 16, 33, 64, 65, 128, 255]
  Или задаются самостоятельно вызовом

    make test TEST_NS="N1 N2 ... N_n"

Сгенерированный тестбенч:

- для `N ≤ 8` перебирает **все** пары `(a, b)`;
- для `N > 8` подаёт граничные случаи (`0`, `1`, `2^N−1`, старший бит, чередующиеся биты — максимальные
  переносы в суммах половин) и случайные пары (равномерные, разреженные, плотные);
- подаёт новую пару на каждом такте и сверяет результат пары `k` на такте `k+3` с эталоном `a·b`.
  Тем самым проверяются значение, задержка ровно 3 такта и конвейерный режим;
- сравнивает через `!==`, поэтому `X`/`Z` на выходе считаются ошибкой.

Эталонное умножение `a*b` используется **только в тестбенче** и в дизайн не попадает.

## Ограничения

- Сгенерированный код — SystemVerilog (`logic`, `always_ff`, `always_comb`); для `iverilog` нужен флаг `-g2012`.
- Глубина комбинационной логики на ступени 2 растёт с `N`, поэтому максимальная тактовая частота при
  синтезе для больших `N` будет низкой — это следствие требования «результат на 3-м такте при любом `N`».
- `iverilog` медленно считает очень широкие числа, поэтому в тестах для `N > 64` используется меньше векторов.
